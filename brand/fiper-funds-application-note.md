## Currency and number rules for this app — precision tied to the data contract (CEO addendum item 9)
Data contract: `docs/money.md` §§ 1, 2, 5 and `packages/shared/src/money.ts` (`Cents`, `MicroUnits`, `MicroDollars`, `MICRO = 1_000_000`, `formatCents`, `formatUnits`, `formatBps`, `divRoundHalfEven`). Every amount is an integer on the wire; display precision follows the **type** and the **currency's minor unit**, never "two decimals for everything".

| Quantity | Storage / API | Display precision | Example | Source |
|---|---|---|---|---|
| Cash amount (USD) | integer **cents** (`amountCents`) | 2 decimals because USD's minor unit is 2 (ISO 4217); another currency would take its own minor unit (JPY 0, BHD/KWD 3) — the registry's `pricingLine.currency` / `listings[].currency` decides the code and the minor unit per line | `125000` → `1,250.00 USD` | `money.md § 1`, `formatCents` |
| Unit price (fund) | integer **cents** | 2 decimals (USD) | `4812` → `48.12 USD` | `money.md § 1` |
| Execution average price | integer **micro-dollars** (`avgPriceMicroDollars`, 1 USD = 1,000,000) | up to 4 decimals, trailing zeros trimmed; never more than the source precision | `48123400` → `48.1234 USD` | `money.md § 1` |
| Unit count | integer **micro-units** (`microUnits`, 1 unit = 1,000,000) | up to 4 decimals, trailing zeros trimmed (`formatUnits`: 6 → 4 places, half-even) | `25976700` → `25.9767`; `4000000` → `4` | `money.md § 5`, `formatUnits` |
| Percentages (returns, expense ratio, purification) | integer **basis points** (bps) | 2 decimals (`formatBps`), space before `%`, sign on deltas | `166` → `1.66 %`; `45` → `0.45 %`; `-84` → `−0.84 %` | `money.md § 4`, `formatBps`, registry `expenseRatioBps`, `purificationRatio.valueBps` |
| Metrics (volatility, drawdown) | bps, display statistics — not money | 2 decimals; labelled as display estimates in the caption | `−1,234` → `−12.34 %` | `money.md § 4` |

- Currency code shown beside every amount (`1,250.00 USD` AR · `USD 1,250.00` EN), never assumed, never `$` inside the app (marketing only). Today the platform is USD-only (`money.md § 1`); the registry already carries `CAD` and `GBP` trading currencies for some funds (`tradingCurrency`) with `pricingLine.convertToUsd` — a converted line shows `USD` and the caption «محوَّل من GBP بسعر المزوّد».
- Sign: `−` (U+2212) in display (the `formatCents` output uses ASCII `-`; the view layer swaps it), `+` only on deltas. Latin digits, `,` thousands, `.` decimal (`money.md § 5`, decision 7.1 in `money.ts`).
- **Zero vs missing**: `0.00 USD` / `0` is a real value (neutral colour, no sign). Missing or not-yet-available data is `—` with the word «لا بيانات» / "No data" (muted), never `0.00`; a pending price shows the last known value with its timestamp or `—`.
- **`finance.loss` vs `state.danger`**: a negative daily change is `--fp-finance-loss` + «خسارة» (a market fact); a failed transfer is `--fp-state-danger` + «فشل» + what to do (a system error). Same colour today, different tokens — never mark a loss as an error or an error as a loss.
- Dates: `fmtDateTime` (`29 أكتوبر 2026، 14:05`) + the zone label (`بتوقيت دبي`); settlement window «16:00 بتوقيت دبي». No ISO strings on any screen (already the rule in `format.ts`).
- Every amount and unit inside `.fp-num` (IBM Plex Mono, tabular, `dir="ltr"`, isolate); `numberingSystem latn`.

## Sharia-certification badge — reflects the documented state only
Source of truth: `data/fund-registry.json` per fund: `sharia.status` (today every listed fund is `"compliant"`), `sharia.certifier` (free-text body, e.g. "Raqaba LLC (Abdulbari Mashal, Ph.D., Managing Partner)" for SPUS; `null`/"None" where the issuer publishes no certifier), `sharia.screeningStandard` (e.g. `AAOIFI`), `sharia.certificateUrl`, `sharia.certificateAsOf`, `sharia.purificationRatio.{valueBps, sourceUrl, asOf, note}`, plus `lastVerified`, `sources[]` and the registry rule «null = جارٍ التوثيق».
- Badge = `fp-badge fp-badge--success` (success token, never brand red) + Lucide `shield-check` 16 px + the word «متوافق مع الشريعة» / "Sharia-compliant" — shown **only** when `sharia.status === "compliant"`.
- The certifier sheet names a certifying body **only** when `sharia.certifier` carries one; with `null`/"None" it says «لم ينشر المُصدر اسم جهة الاعتماد» / "Certifier not published by the issuer" and shows `lastVerified`. Never imply a certificate, a standard or a scholar that is not in the record; never show Fiper itself as the certifier.
- `certificateUrl` → a button («الشهادة» / "Certificate"), never a raw URL; `certificateAsOf` shown as a human date next to it.
- `non_compliant` → muted outline chip «غير متوافق» (never red); `null` (documenting) → warning chip «جارٍ التوثيق» with `checkedOn`/`lastVerified`. Purification shows `purificationRatio.valueBps` via `formatBps` with its `asOf` and `note` in the caption.
- Any wording beyond the registry fields is PROPOSED and must say so; compliance claims in marketing captions stay within `fnd.dis` (`glossary.md` § 5) until the regulatory decisions in `regulatory-matrix.md` are taken.

## Empty / pending / settled
- Empty: title sentence + one-line body + one primary CTA (`EmptyState`); mark 48 px muted optional, no illustration.
- Loading: skeleton rows (`.fp-skeleton`, 56 px, ash shimmer 1.2 s linear, reduced-motion → static), never a spinner over content (the `Spinner` only on the auth gate).
- Pending: warning badge + clock + settlement time with zone; row stays in place, no animation.
- Settled: success badge + check + settled date; amount colour by sign.
- Error: `ErrorState` with the named cause and a retry button (secondary).
