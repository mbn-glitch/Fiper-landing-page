Why no dark variant (decision 31 Oct 2026): Gmail strips `<style>` dark-mode media queries in some apps and auto-inverts colours, Outlook Windows rewrites them, Apple Mail honours `prefers-color-scheme` — the same template renders three different "dark" mails that cannot be controlled or tested from here. One paper rendering with `color-scheme: light only` is the controllable outcome; a client's own inversion of the paper ground remains legible (dark text on light → light text on dark). Other known behaviours to verify when accounts exist: Outlook Windows ignores `border-radius` (pill buttons render square — accepted) and `background` on `<td>` needs `bgcolor`.

## Raw-URL rule
Visible text must contain no URL; `href` and `img src` may carry URLs. Check used (per file, tags stripped, exit code 1 on a hit):

```sh
for f in brand/templates/email/*.html; do
  python3 - "$f" <<'PY'
import re,sys,html
s=open(sys.argv[1],encoding='utf-8').read()
s=re.sub(r'<(style|script)[^>]*>.*?</\1>','',s,flags=re.S|re.I)
text=html.unescape(re.sub(r'<[^>]+>',' ',s))
hits=re.findall(r'https?://\S+|www\.\S+',text)
print(sys.argv[1], 'raw URLs in visible text:', len(hits)); sys.exit(1 if hits else 0)
PY
done
```
Result on 31 Oct 2026 (v2.3.2): `base 0 · otp 0 · confirmation 0 · statement 0 · base.en 0 · otp.en 0 · confirmation.en 0 · statement.en 0` (PASS).
