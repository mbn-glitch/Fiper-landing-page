# Deliverables manifest — Fiper Brand Identity System v2.3.4 (1 Nov 2026)

Maps every requirement (task file sections A–N, package items 1–3, Fiper Funds items, CEO addendum items 1–13) to its output file(s). Columns: file · format · editing tool · status · acceptance; the "Preview ≠ deliverable" column names rows where only a rendered preview exists for a format (a preview never counts as the deliverable). Gate: `node scripts/check-manifest.mjs` (every path named here must exist). Status: **DONE** · **PARTIAL** (with what is missing) · **NOT PROVIDED** (with reason) · **DONE (lead) — see qa-report.md** (produced by the lead after this manifest was written). Paths are relative to the package root (`brand/`) unless they start with `dist/`, `manual/` or `scripts/` (repo root). "Editing tool" = what a human opens to change it.

Version v2.0 = the approved v1.2.1 composition direction generalised to every deliverable below; file names and references unified to v2.0.1 (git tag `v2.0.1`); v2.0.0 superseded by the limited correction round.0. Status column: DONE (v2.0 file present and checked) · PARTIAL · NOT PROVIDED (reason) · NOT TESTED (reason) · DONE (v2.0 build; evidence in qa-report.md § 1–5) (regenerated by the lead in the v2.0 build: manual PDF, zip, previews, unzipped-copy verification). Earlier artefacts are ARCHIVED in `dist/archive/v1.x/` (see `dist/archive/README.md`) and are not deliverables.
